# TQBot2 滚动策略评估协议

本协议回答五个问题：是否能持续滚动、是否按滚速命令运动、是否按偏航命令运动、课程被什么卡住、脱离辅助或改变环境后是否仍成立。奖励曲线只用于诊断优化过程，不能替代任务验收。

## 一次完整评估应交付什么

| 问题 | 必须报告的指标 | 如何判断 |
|---|---|---|
| 有效运动是否成立 | 回合时长、失败原因、完整圈数、无完整圈比例 | 无完整圈是失败，不是零误差 |
| 是否跟踪滚速 | 每圈相对误差、按命令分箱的实际速度、回合成功率 | 命令增加而实测不变，说明没有学会速度调节 |
| 是否跟踪偏航 | 每圈绝对误差的均值/P50/P80/P95、超标率、回合成功率、命令响应 | 零命令是直滚任务；通过零命令不代表会转弯 |
| 两项能否同时完成 | 滚速合格/偏航合格的 2×2 回合分组、联合成功率 | 明确是偏航单项、滚速单项还是两者失败 |
| 课程差多少 | 滚速成功率距 75%、联合成功率距 70% 的百分点差及区间 | 不拿平均误差与单圈阈值作晋级判据 |
| 策略是否可部署 | 均值动作与训练高斯采样各自的效果 | 部署策略必须单独评估；两者不能混报 |
| 是否动作饱和 | 每关节原始动作越界率、均值越界率、正/负限位比例、标准差 | 标准差不是收敛判据；裁剪后的实际动作才影响机器人 |
| 动作质量 | 修正 base 的 Z 加速度 RMS、功率、轨迹、失败回放 | 20ms 指标不等同于 5ms 冲击峰值 |
| 能否泛化 | 无初速且全相位、非零偏航、上下坡的分条件结果 | 区分当前课程验收与未训练条件压力测试 |

## 固定统计口径

每个回合从重置到终止/10 秒时限。一个完整滚动圈为负方向净滚动角达到 2π；倒滚会扣除进度。每圈角速度按实际持续时间平均。

- 单圈滚速：`abs(mean_roll - command_roll) <= 0.2 * abs(command_roll)`。
- 单圈偏航：`abs(mean_yaw - command_yaw) <= 0.06 rad/s`。
- 有效回合：持续至少 6 秒、完成至少 4 圈。
- 滚速成功回合：有效且至少 80% 圈滚速合格。
- 偏航成功回合：有效且至少 80% 圈偏航合格。
- 联合成功回合：上述两项均成立。不是要求同一组 80% 圈同时合格。
- 所有失败回合计入分母。误差均值无法定义时写 `null` 并报告覆盖率，不补零。
- 同时给出“所有圈等权均值”和“每回合先平均再等回合权重均值”，标明分母。

课程在线判定要求至少 2048 回合、距上次判定至少 500 控制步，滚速成功率 ≥75%、联合成功率 ≥70%，连续两批满足。滚动课程按初速辅助→相位→偏航轮换推进。坡度课程单独按当前边界子集统计，另有沿坡前进距离条件，因此不能拿坡度升级推断联合课程过关。

冻结模型的独立评估能估计离这些门槛多远；不能声称重现训练中某个未保存的批次。要作正式接近门槛的验收，增大样本直到区间足够窄；建议两个独立评估批次，每批至少 2048 回合，并检查置信区间下界，而非只看点估计。这是比当前代码更严格的离线验收建议，不是声称训练代码已采用该区间判据。

## 场景和抽样

当前脚本保持 200Hz 物理、50Hz 控制、10 秒回合、窄物理随机化与观察噪声。每个环境抽样后保留固定的质量/质心/材料，每回合重抽增益和初始状态。每个环境取相同数量完整回合，防止快速失败的环境反复重置而占据更多样本。

| profile | 滚速命令 | 偏航命令 | 初速与相位 | 坡度 | 用途 |
|---|---|---|---|---|---|
| current | 均匀 −14～−6 | 0 | 辅助 1；−2±0.1 | 20% 平地、40% 0～2°上坡、40% 0～3°下坡 | D 当前课程能力估计 |
| flat | 均匀 −14～−6 | 0 | 同上 | 0° | 平地基准 |
| unassisted | 均匀 −14～−6 | 0 | 辅助 0；−2±π | 0° | 启动与全相位泛化 |
| yaw_probe | −10 | −0.5、−0.25、−0.1、0、0.1、0.25、0.5 | 辅助 1；−2±0.1 | 0° | 超出当前课程的偏航响应 |
| slope_probe | −10 | 0 | 辅助 1；−2±0.1 | −30、−20、−10、0、+5、+10° | 超出当前课程的坡度压力测试 |

`current` 明确冻结为此次评估的 2°/3°课程，不会自动读取后续训练的新课程等级。下次课程改变必须同步修改评估 profile 并记录，不能把旧条件结果冒充新条件结果。

建议每个场景分别测试高斯采样（训练策略）和确定性均值（部署策略）。计划矩阵见输出目录 `plan.json`，但此次只完成 D/model_14000 的一个评估种子、128 个环境各两个回合，共 256 回合。用户要求优先分析已有训练日志后，扩展矩阵停止，未完成项不能当作已测结果。即使做三个评估种子，也只估计同一模型在不同环境中的变化，不是三次从头训练。若要证明奖励设计更好，需要相同初始化、相同预算、至少多个独立训练种子；C 从头与 D 续训不能作干净的奖励消融。

95% 区间按 `(seed, env)` 整组 bootstrap，保留同一环境内多个回合共享物理参数带来的相关性。逐圈样本数量多不代表同等数量的独立试验。

## 一条命令重现

在 `/home/eureka/robot_lab` 执行：

```bash
bash scripts/roll/run_evaluation.sh outputs/rolling_policy_audit_20260929/plan.json outputs/rolling_policy_audit_repeat
```

脚本不训练、不推进课程、不停止已有训练。默认 128 并行环境、每环境两个回合。输出目录中已完成的 case 会跳过；使用新的目录可以完整重做。不要在改动计划、代码或环境参数后复用旧输出目录。

计划中的每项包括 `name, label, checkpoint, profile, sampling, seed`。模型使用当前 35 维观察、6 维动作、ELU MLP 512/256/128、高斯直接标准差，严格加载所有状态键；不兼容的模型会失败，不会静默近似。统一评估奖励为 B 形式、偏航权重 10，主要验收指标不依赖奖励。

手动命令：

```bash
OMNI_KIT_ACCEPT_EULA=YES /home/eureka/miniconda3/envs/isaaclab/bin/python -u scripts/roll/evaluate_policy.py \
  --plan outputs/rolling_policy_audit_20260929/plan.json \
  --output outputs/rolling_policy_audit_repeat \
  --num-envs 128 --episodes-per-env 2 --max-steps 1010 --headless --device cuda:0
/home/eureka/miniconda3/envs/isaaclab/bin/python scripts/roll/report_evaluation.py \
  --input outputs/rolling_policy_audit_repeat
```

若将 `--episodes-per-env` 改为 N，`--max-steps` 至少应为 `500*N+10`。GPU 小批次会缩小接触缓存分配容量，物理参数不变；日志出现容量溢出时结果无效，需要扩大容量后重跑。独立评估会争用计算资源，影响训练墙钟速度。

产物：`report.md`、`aggregate.json`、六图 dashboard、每个 case 的逐回合 `episodes.json`、逐圈 `cycles.json`、`summary.json`、稀疏 `traces.csv`、质量/质心 `physics.json`、有效 `evaluation_env.yaml`。轨迹保存前 8 个环境供定位，不代替全样本统计。

## 正常的监测节奏与决策

1. 开训前：固定验收指标、命令网格、种子、失败定义与初始条件；保存代码、配置、模型来源和预算。
2. 训练中：连续观察回合长度/终止原因、奖励分项、动作分布、课程等级；每 200～500 迭代对冻结检查点跑固定评估集。对比相同条件，避免课程难度变化制造假退化或假进步。
3. 发现退化：先排除观测/动作/奖励/统计错误，再区分启动失败、命令无响应、偏航长尾和动作饱和。一次只改变一个主要因素。
4. 检查点选择：按联合成功率和分条件最差表现选择，不默认最后一个最好。保留独立最终测试集，避免反复看同一测试种子后过拟合调参。
5. 定型前：更多种子和回合、均值策略无辅助全相位、命令切换响应、目标坡度、噪声/扰动，再做 sim-to-sim/实机检查。此次矩阵没有外力扰动和动态命令切换，不能据此声称全场景通过。

后续训练应额外写入每批分子/分母：完整圈数、yaw_good、roll_good、有效回合数、滚速/偏航/联合成功回合数、课程 pass/streak，以及命令分箱。当前运行进程未保存的历史统计无法靠日志后处理恢复；本次没有热改运行中的训练过程。

## 方法依据

- [Stable-Baselines3 评估建议](https://stable-baselines3.readthedocs.io/en/master/guide/rl_tips.html)：独立测试环境、区分探索与确定性策略、多次运行。
- [Deep RL at the Edge of the Statistical Precipice](https://arxiv.org/abs/2108.13264)：关注有限样本不确定性、区间与可靠聚合，不靠单条曲线下结论。

这里的阈值和协议是项目任务定义；上述文献并没有为本机器人规定 0.06 或 70% 的通用数值。
